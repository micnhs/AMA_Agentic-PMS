## Context

Critical cases need a dashboard alert and an e-mail within 60 seconds (pilot target); never to
authorities or real persons.

## Options

- **A** – Locally an outbox folder; in Azure, Azure Communication Services Email with an Azure-managed
  domain.
- **B** – Microsoft Graph `sendMail`.
- **C** – Dashboard only.

## Decision

Proposal **A**: recipients only from configuration (demo mailboxes of the deployer); content only case
ID, critical reason and link, no letter text. Alert worker with at least one running instance.

## Consequences

Communication Services is a global service with data location Europe; the delivery path is not limited
to one region (OI-012). Managed identity preferred, otherwise a connection string only in Key Vault.

## Implementation in this repository (not part of the concept text)

- Recipients come from `ALERT_RECIPIENTS` (default: `DEPLOYER_EMAIL`); the preflight checks that every
  entry is an e-mail address. Use demo mailboxes only.
- The app sends with its user-assigned managed identity and a least-privilege custom role
  *PMS demo ACS e-mail sender*; no access key or connection string is used, and Key Vault stays empty.
- The alert, the triage task and the audit record are written together with the rule results, before
  any analysis starts. Offline the outbox entry follows at once. In Azure the e-mail never blocks the
  upload: a background thread of the web app sends it (waiting at most 15 seconds for the service),
  records `SENT` or `FAILED` and keeps a copy (`.eml` and `.json`) in the Blob container `outbox`.
- The alert and analysis worker (`ca-worker-*`, exactly one replica at all times) retries alerts that are
  still pending after 10 seconds and failed ones after 5, 15, 45 and 135 seconds, at most 5 attempts; a
  delivery claim keeps two processes from sending the same alert. The web app may scale to zero.
- The e-mail links to the case with an absolute URL: Bicep sets `PUBLIC_BASE_URL` to the web address.
- As a second barrier, the app refuses recipients that are not configured and recipients whose domain
  looks like a public-authority domain (`src/pms/notify.py`).
- Offline, every alert is written to the local outbox `DATA_DIR/outbox` (one `.eml` and one `.json` file);
  no e-mail is sent.
