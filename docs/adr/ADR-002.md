## Context

One EU region for all resources; processing in the EU data zone. On 10 Nov 2026 Michael asked for a
more capable model that can call tools and carry out medical analyses more thoroughly (R-18).

## Options

- **A** – gpt-6-astra for all agents.
- **B** – gpt-6-astra for A3 and A6, gpt-6.1-sol for A1, A2 and A4.
- **C** – gpt-6.1-sol for all agents.

The earlier proposal gpt-5.4-mini is dropped (no function tools in the Agent Service).

## Decision

Decided on 10 Nov 2026 (Q-10, option **B**), each as **Data Zone Standard EU in Sweden Central**: the
strongest model where medical analysis and correlation happen; gpt-6.1-sol, with almost the same
performance at about one fifth of the price, for reading, matching and the report draft.

Fallback model: **gpt-6.1-sol for all agents, never Global Standard.**

| Agent | Model deployment |
|---|---|
| A1 Signal ingestion | gpt-6.1-sol |
| A2 Product and implant matching | gpt-6.1-sol |
| A3 Medical analysis and causality | gpt-6-astra |
| A4 Vigilance reporting (drafts) | gpt-6.1-sol |
| A5 Light trend view | no model |
| A6 Evidence and correlation | gpt-6-astra |

## Consequences

Both models support the Responses API, function calling and structured outputs (Microsoft Foundry,
September 2026). According to the Microsoft Learn table (10 Nov 2026) both are available as Data Zone
Standard EU in Sweden Central; a Foundry announcement from September lists only the US data zone for
Astra (OI-010). The preflight script therefore checks model, version, deployment type and quota.
No model is clinically validated; evaluation uses the golden set and Foundry evaluators (T30).
Michael chose option B on 10 Nov 2026 (Q-10).

## Implementation in this repository (not part of the concept text)

- `infra/models.json` is the single source for both deployments: `gpt-6-astra` version `2026-09-03`
  (agents A3, A6) and `gpt-6.1-sol` version `2026-09-29` (agents A1, A2, A4), deployment type
  `DataZoneStandard`, version upgrade disabled.
- The app reads the deployment names from `MODEL_DEPLOYMENT_ANALYSIS` (A3, A6) and
  `MODEL_DEPLOYMENT_GENERAL` (A1, A2, A4).
- Fallback: `azd env set MODEL_FALLBACK_ALL_GENERAL true` deploys only gpt-6.1-sol and uses it for all
  agents.
- `GlobalStandard` is refused by the Bicep parameter (`@allowed`) and by the preflight check.
  The templates also accept `Standard` (processing in the selected EU region only) as an alternative
  deployment type; the concept decision remains Data Zone Standard.
- Token prices for the cost view are kept in a dated price table (`config/pricing.json`, 10 Nov 2026):
  gpt-6-astra 11 USD input and 55 USD output, gpt-6.1-sol 2.20 USD input and 11 USD output per
  1 million tokens (Data Zone). The EU data zone price factor is not confirmed (OI-031).
