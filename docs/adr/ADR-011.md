## Context

At the approval on 10 Nov 2026, Michael asked that the best practices of the Azure Well-Architected
Framework be followed (R-20). Partners shall be able to deploy the demo without help, and it shall stay
inexpensive.

## Options

- **A** – Full production baseline (zone redundancy, private networking, Defender plans, second region).
- **B** – A demo baseline aligned with the Well-Architected Framework: free and low-cost recommendations
  on by default, paid ones as documented deviations with an option.
- **C** – No explicit alignment.

## Decision

**B.** Measures per pillar as in concept section 6.11 (table below); PSRule for Azure checks the Bicep
templates in CI; deviations are listed with their reasons in the README.

## Consequences

No new paid services; options with extra cost only with Michael's approval (OI-037). The demo illustrates
the alignment; it is not a statement of conformity.

## Measures per pillar (concept section 6.11)

| Pillar | Implemented in the demo | Deliberate deviation and option | Check |
|---|---|---|---|
| Reliability | Alert worker with at least one replica and health probes; retry with backoff for model and search calls; idempotent processing per signal; resume after a failure without lost deadlines; infrastructure as code, repeatable with azd | No zone redundancy and no second region (cost, demo); option: zone-redundant environment and Cosmos DB (OI-037) | T25, T29, smoke test |
| Security | Sign-in only through Microsoft Entra ID with app roles; managed identities instead of keys; local authentication of the services off where the service allows it; Key Vault with RBAC, soft delete and purge protection; HTTPS only; least privilege; Prompt Shields; secret scan; deployment through OIDC without stored secrets | Public endpoints protected by Entra ID instead of private networking; Defender plans not enabled; option: VNet integration with private endpoints (OI-037) | T05, T11, T31, T32 |
| Cost optimization | Serverless and Basic tiers, budget with alerts, costs per case, forecast for the next month, tags for cost allocation, teardown script | Azure AI Search Basic is the largest fixed cost item; the tier is a parameter (OI-035) | T27, T28 |
| Operational excellence | Everything as code (Bicep, azd); CI with lint, tests, Bicep build and Well-Architected check; preflight and smoke test; diagnostic settings to Log Analytics; workbook and alert rules; versions in every audit record | No staging environment (demo) | T09, T10, T29, T31 |
| Performance efficiency | Container Apps scale with load; limits for tool calls, rounds and run time; measurement of the alert latency | No load tests (demo volume) | T04, T29 |

Checks: PSRule for Azure checks the Bicep templates in CI against the Well-Architected rules (pinned
version; exceptions only with a written reason in the configuration, T31). The preflight script checks
region, quotas and rights. The deviations are listed in the README under limits. After the deployment,
Michael can also use the Well-Architected Review and Azure Advisor; neither is part of the automated
checks.

## Implementation in this repository (not part of the concept text)

- CI job `psrule` runs PSRule 2.9.0 with PSRule.Rules.Azure 1.39.0 on `infra/tests/main.tests.bicep`
  (options in `ps-rule.yaml`) and uploads a SARIF report.
- Deviations are suppression groups in `.ps-rule/waf-deviations.Rule.yaml`, each with its written reason:
  public endpoints instead of private networking; no zone or geo redundancy; Azure AI Search with one
  replica (no SLA); Azure Container Registry Basic (approved, Q-6); no Defender for Cloud plans; web app
  scale-to-zero and a single alert worker.
- Further known deviations: Application Insights still accepts ingestion with its connection string
  (needed by the Foundry tracing connection); Communication Services access keys cannot be disabled with
  the API version used (the app uses Entra ID only).
- Low-cost option available as a parameter: `AZURE_STORAGE_SKU=Standard_ZRS` (zone-redundant storage).
  Private endpoints, Defender plans and zone-redundant Container Apps are not offered as parameters
  (extra cost; they would need approval).
