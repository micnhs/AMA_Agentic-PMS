## Context

Agents shall draw on further sources and correlate them. All inputs must be invented; no mass ingestion,
no internet; results must be the same and testable offline and in Azure.

## Options

- **A** – Deterministic search in the app.
- **B** – File Search of Foundry Agent Service.
- **C** – Azure AI Search.

## Decision

Decided on 10 Nov 2026 (Q-8): **C**, Azure AI Search in the **Basic** tier (73.73 USD per month, list
price of 10 Nov 2026), an index of the fictional corpus with keyword search and filters on type, family,
model, lot and event term. A6 calls the search as a read-only function tool; the app checks the
parameters and queries the index. Offline, SQLite FTS5 replaces the index behind the same search
contract.

## Consequences

The mandatory correlations (CORR-1.0) stay deterministic: exact filter queries return the same hits
offline and in Azure (T21). The corpus version is in every audit record. The Free tier (one service per
subscription) or Serverless (preview) is possible as a parameter (OI-035).

## Implementation in this repository (not part of the concept text)

- Fictional corpus: `data/synthetic/knowledge/` (9 literature summaries, 5 technical documents, 5 past
  cases, 3 process findings; corpus version in `knowledge_index.json`). Every item is marked as fictional.
- The app creates and fills the index `pms-knowledge` (`AZURE_SEARCH_INDEX`) with its Microsoft Entra
  identity (key authentication is disabled): at `python -m pms seed --index-only` (postdeploy hook), at
  every worker start and before the first query of a process. The index holds exactly the documents of
  the offline index (corpus plus dossier side-effect items); documents are compared by content hash, so
  a sync is idempotent (`--force` uploads all again). Queries are read-only. Exact filters are checked
  again locally, so filter-only queries – and with them the CORR-1.0 correlations – return the same hits
  in the same order as offline; for text queries the matched set is the same, the ranking can differ
  (`src/pms/azure/search.py`).
- Search arguments are validated against an allow-list (no addresses or links, few words, limited
  hits); letter text never becomes a query, so an injected instruction cannot steer a search.
- The tier is the azd parameter `AZURE_SEARCH_SKU` with the values `free`, `basic` (default) and
  `standard`. Serverless is not offered as a parameter. Whether the Free tier works with the keyless
  access used here is not verified.
