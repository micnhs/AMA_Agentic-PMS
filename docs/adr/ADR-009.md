## Context

Michael asks for governance and monitoring functions. The demo shall make operation, quality and
controls visible without depending on preview features.

## Options

- **A** – Azure Monitor only.
- **B** – Foundry tracing (generally available for prompt agents) with Application Insights, plus Azure
  Monitor, Azure Policy and content filters.
- **C** – Additionally preview features (agent monitoring dashboard, continuous evaluation, red teaming,
  insights).

## Decision

Proposal **B** as default, **C** as an option that can be switched off. Workbook and alert rules through
Bicep: alert latency above 60 seconds, failed agent runs, failure of the alert worker, failed audit-chain
check, budget levels. Azure Policy allows only the selected region. Content filter with Prompt Shields
against direct and indirect attacks. Governance view in the app: versions, evaluation status, open human
decisions, deadlines, audit status.

## Consequences

Traces contain prompt content; read access only for the operator role (A-16, OI-033). Retention 30 days
(parameter). Preview features stay off until Michael enables them (OI-032).

## Implementation in this repository (not part of the concept text)

- `infra/modules/observability.bicep`: action group (deployer e-mail), four log alert rules evaluated
  every 15 minutes (critical-case alert later than 60 seconds; failed agent runs; alert-worker heartbeat
  missing; audit-chain verification failed) and the workbook *PMS agent demo – operations*.
- `infra/modules/governance.bicep`: policy *Allowed locations* (enforced, selected region only), policy
  *Require a tag on resources* (`workload`, report only) and the budget with notifications.
- `infra/modules/foundry.bicep`: content filter `pms-prompt-shields` (jailbreak and indirect-attack
  protection plus harm filters) on both model deployments; `CUSTOM_CONTENT_FILTER=false` falls back to
  the built-in default policy. The filter configuration is to be confirmed (OI-034).
- Log Analytics keeps data 30 days (`LOG_RETENTION_DAYS`) with a daily cap of 1 GB (`LOG_DAILY_CAP_GB`)
  and uses resource-permission access, so reading traces in Azure needs Azure RBAC on the monitoring
  resources.
- `PREVIEW_MONITORING=false` by default; do not switch it on without the project owner's approval.
