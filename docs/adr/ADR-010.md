## Context

Michael asks for consumed platform and model costs, a forecast for the next month and costs per case.

## Options

- **A** – Azure portal only (Cost Management).
- **B** – A cost service in the app with token costs per run and the Cost Management APIs (Query,
  Forecast), plus a budget.
- **C** – Own export to a store with evaluation.

## Decision

Proposal **B**: model costs per agent run from the token usage of the Responses API and the dated price
table; platform costs of the resource group through the Query API (start of month to today, by service);
forecast for the next month through the Forecast API, otherwise a labelled simple projection; costs per
case as measured variable costs plus a separately shown share of the fixed costs. Budget through Bicep
(default 250 USD per month; notifications at 50, 80 and 100 percent actual and 100 percent forecast to
the deployer address).

## Consequences

The app's managed identity has the role *Cost Management Reader* on the resource group. Not every
subscription type supports the APIs; then the app shows only token costs and a notice (OI-030).
Offline: simulated, labelled cost data.

## Implementation in this repository (not part of the concept text)

- Dated price table `config/pricing.json` (USD per 1 million tokens, source and date 10 Nov 2026).
- `COST_SCOPE` (resource group ID) and `BUDGET_USD` (default 250) are set as app settings by Bicep.
- Budget notifications go to `DEPLOYER_EMAIL`. A budget only notifies; it does not stop spending.
- Actual costs from Cost Management arrive with a delay of up to about one day (A-15); the forecast is an
  estimate. Cost values are kept apart from safety and trend views and are not a statistical statement
  about products (K-19).
- The preflight warns (does not fail) when the Cost Management API does not answer for the subscription.
